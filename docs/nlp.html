Natural Language Processing

Natural Language Processing

NLP is a subfield of artificial intelligence (AI), computer science, and linguistics focused on enabling computers to understand, interpret, and generate human language in a way that is meaningful and contextual.

Think of it as the bridge between human communication (which is nuanced, ambiguous, and culturally rich) and machine computation (which relies on numbers and logic).

Core Tasks

  • Text Classification: Categorizing text into predefined labels (e.g., spam detection, sentiment analysis of product reviews).
  • Named Entity Recognition (NER): Extracting key entities from text, such as names, dates, organizations, or medical terms.
  • Machine Translation: Automatically translating text or speech from one language to another (e.g., Google Translate).
  • Text Summarization: Condensing long documents or articles into short, cohesive summaries.
  • Question Answering & Conversational AI: Building systems (like chatbots or virtual assistants) that can parse a query and retrieve or generate precise answers.

The Evolution: From Linguistics to Transformers

  1. Traditional NLP (Rule-Based & Statistical): Early systems relied on heavy human intervention, grammar rules, regular expressions, and statistical models like TF-IDF and Naive Bayes.
  2. Deep Learning Era: The introduction of Recurrent Neural Networks (RNNs) and LSTMs allowed models to process sequences of words and capture short-term context.
  3. The Transformer Revolution: Modern NLP is dominated by Transformer architectures (like BERT, GPT, and T5) powered by self-attention mechanisms. These models process entire sentences in parallel, capturing deep, nuanced context across massive datasets.

The NLP Workflow

Workflows for NLP tasks typically follows these stages:

Stage Description Common Tools / Techniques
1. Data Collection & Cleaning Gathering text from APIs, web scraping, or databases, and removing noise (HTML tags, special characters). Python (BeautifulSoup, Regex), Pandas
2. Text Preprocessing Standardizing the text for the model. Tokenization, Lowercasing, Stop-word removal, Lemmatization
3. Vectorization / Embeddings Converting words or documents into numerical vectors that computers can process. Word2Vec, GloVe, Contextual Embeddings (Hugging Face)
4. Modeling & Fine-Tuning Training a model or fine-tuning a pre-trained Large Language Model (LLM) for your specific task. PyTorch, TensorFlow, Hugging Face transformers, Scikit-learn
5. Evaluation & Deployment Measuring performance using metrics like Accuracy, F1-Score, BLEU, or ROUGE, and deploying via APIs. MLflow, FastAPI, Docker

Example Tasks

Text Classification

The Text Classification Workflow

A text classification pipeline involves five sequential steps:

  1. Data Collection & Preparation: Gathering the text dataset and ensuring the target labels are clean and well-defined.
  2. Train-Test Splitting: Partitioning the data to prevent data leakage and evaluate the model objectively on unseen data.
  3. Text Feature Extraction (Vectorization): Machine learning algorithms require numerical inputs, not raw strings. One must convert text into numerical vectors using techniques like TF-IDF (Term Frequency-Inverse Document Frequency) or Bag-of-Words.
  4. Model Training: Fitting a classification algorithm (such as Logistic Regression, Naive Bayes, or Support Vector Machines) to the training features.
  5. Evaluation: Assessing performance using robust metrics like Accuracy, Precision, Recall, F1-Score, and a Confusion Matrix.
End-to-End Pipeline
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score, classification_report, confusion_matrix
from sklearn.model_selection import train_test_split
from sklearn.pipeline import Pipeline

# 1. Sample Dataset (Texts and corresponding binary labels: 1 = Positive, 0 = Negative)
texts = [
    "I absolutely love this product! It exceeded all my expectations.",
    "Worst purchase I have ever made. Complete waste of money.",
    "Pretty decent quality for the price, though shipping was a bit slow.",
    "Terrible customer service and the item arrived broken.",
    "Fantastic experience! Will definitely buy again.",
    "Not worth it at all. Stopped working after two days.",
    "Impressed by the build quality and sleek design.",
    "Awful. Do not buy this garbage.",
]
labels = [1, 0, 1, 0, 1, 0, 1, 0]

# 2. Split into Training and Test Sets (80% train, 20% test)
X_train, X_test, y_train, y_test = train_test_split(
    texts, labels, test_size = 0.2, random_state = 42, stratify = labels
)

# 3. Build a scikit-learn Pipeline combining Vectorization and Modeling
# Pipeline ensures text is transformed consistently during both training and inference
model_pipeline = Pipeline(
    [
        (
            "tfidf",
            TfidfVectorizer(stop_words = "english", ngram_range = (1, 2)),
        ),  # Converts text to TF-IDF features
        ("classifier", LogisticRegression(random_state = 42)),  # Classification model
    ]
)

# 4. Train the Model
model_pipeline.fit(X_train, y_train)

# 5. Make Predictions on the Test Set
y_pred = model_pipeline.predict(X_test)

# 6. Evaluate Performance
accuracy = accuracy_score(y_test, y_pred)
print(f"Accuracy: {accuracy:.4f}\n")

print("Classification Report:")
print(
    classification_report(
        y_test, y_pred, target_names=["Negative", "Positive"], zero_division = 0
    )
)

print("Confusion Matrix:")
print(confusion_matrix(y_test, y_pred))

# Example: Predicting a new, unseen text
new_reviews = [
    "Amazing quality, I am thoroughly impressed!",
    "Horrible experience, never coming back.",
]
predictions = model_pipeline.predict(new_reviews)
for review, pred in zip(new_reviews, predictions):
    sentiment = "Positive" if pred == 1 else "Negative"
    print(f"Review: '{review}' --> Predicted: {sentiment}")

Best Practices

  • Leverage Pipelines: Always wrap the text vectorizer and model inside a sklearn.pipeline.Pipeline. This prevents data leakage (where test statistics accidentally influence training vectorization) and simplifies deployment.
  • Handle Imbalanced Data: If one class heavily dominates your dataset (e.g., 98% non-fraudulent transactions), rely on F1-Score, Precision, and Recall rather than raw accuracy.
  • Experiment with N-grams: Including unigrams (single words) alongside bigrams (ngram_range = (1, 2)) helps capture short contextual phrases like “not good” instead of just treating words independently.

Named entity Recognition

Named Entity Recognition is a subtask of Information Extraction that seeks to locate and classify named entities mentioned in text into predefined categories, such as Persons, Organizations, Locations, Dates, Monetary Values, and more.

The Named Entity Recognition Workflow

Building and applying an NER pipeline involves four primary stages:

  1. Text Preprocessing & Tokenization: Cleaning the raw text and splitting it into individual words or tokens while preserving sentence boundaries.
  2. Feature Engineering / Representation: Transforming tokens into numerical or vector representations (such as word embeddings or part-of-speech tags) for traditional machine learning, or feeding raw sequences directly into deep learning architectures.
  3. Model Training & Sequence Labeling: Using sequence labeling algorithms — such as Conditional Random Fields (CRFs), BiLSTM-CRFs, or state-of-the-art Transformer models (like BERT/RoBERTa via Hugging Face) — to predict entity tags (often encoded using schemes like IOB: Inside, Outside, Beginning).
  4. Post-Processing & Evaluation: Extracting the recognized entity spans, mapping them to their canonical types, and evaluating performance using entity-level Precision, Recall, and F1-Score.
NER with spaCy

In modern data science, one rarely trains an NER model from scratch unless one has specialized domain corpora (like medical records or legal contracts). Instead, one uses robust pre-trained libraries like spaCy or Hugging Face Transformers.

A clean, reproducible script using spaCy to perform off-the-shelf Named Entity Recognition:

import spacy

# 1. Load the pre-trained English language model
# Make sure to download the model first via: python -m spacy download en_core_web_sm
nlp = spacy.load("en_core_web_sm")

# 2. Sample Unstructured Text Document
text = (
    "Apple Inc. CEO Tim Cook announced a new flagship store opening in "
    "San Francisco on October 5th, 2026, priced at roughly $10 million."
)

# 3. Process the text through the spaCy pipeline
doc = nlp(text)

# 4. Extract and Inspect the Recognized Named Entities
print("Extracted Named Entities:\n" + "-" * 40)
for ent in doc.ents:
    print(f"Entity: {ent.text:<20} | Type: {ent.label_}")

# 5. Visualizing or exporting token-level IOB tags
print("\nToken-Level Details (Text, POS, Tag, IOB Entity Scheme):\n" + "-" * 50)
for token in doc:
    print(
        f"{token.text:<12} | {token.pos_:<6} | {token.tag_:<6} | {token.ent_iob_}-{token.ent_type_}"
    )

Best Practices

  • Understand IOB Tagging Schemes: Most sequence labelers use B- (Beginning), I- (Inside), and O (Outside). For instance, “San Francisco” would be tagged as B-LOC followed by I-LOC. Ensuring correct scheme handling is vital when building custom models.
  • Leverage Transfer Learning: For domain-specific tasks (e.g., extracting legal clauses or biomedical genes), fine-tuning a pre-trained transformer model using frameworks like Hugging Face transformers yields vastly superior results compared to rule-based or traditional machine learning approaches.
  • Entity Disambiguation & Linking: Recognizing an entity is just step one. Real-world systems often require Entity Linking to tie a mention (like “Apple”) to a unique knowledge base ID (such as Wikidata Q312) to resolve ambiguity.
